# Architecture rules

Enforced by `biome.json` (`overrides` → `noRestrictedImports`). A violation fails
`pnpm lint`, which runs in the pre-commit hook. Do not weaken the rule to make a
change fit; move the code instead.

## Layers

Dependencies point downward only. A layer may import anything below it, never above.

```
app/          shell: routing, providers, global layout, i18n bootstrap
  ↓
features/     vertical slices — the unit of deletion
  ↓
components/   shared presentational components (ui/ is shadcn)
  ↓
lib/          pure helpers, no I/O, no React
ipc/          the only module allowed to reach the main process
```

`features/` may import `ipc/`, `components/`, `lib/`.
`ipc/` imports nothing from the app.

## Rules

1. **Features never import each other.** Inside a feature use relative paths
   (`../use-terminal-session`). If two features need the same thing, promote it to
   `components/` or `lib/` — do not reach sideways.
2. **Features are at most two directories deep.** `features/x/components/Y.tsx`,
   `features/x/hooks/z.ts`. Deeper nesting collides with the `../../` ban, and is
   a sign the feature should be split.
3. **Only `src/ipc/**` touches the preload bridge.** Every command gets a wrapper
   in `ipc/client.ts` returning `IpcResult<T>`; every shell capability gets one in
   `ipc/platform.ts`. Callers never see `window.asdf`.
4. **`src/components/ui/**` is generated by the shadcn CLI.** Treat it as vendor
   code. Wrap it, do not edit it. It is excluded from knip for that reason.
5. **`src/lib/**` stays pure.** No React, no IPC, no components. If a helper needs
   state, it belongs to a feature.

## Main process side

```
electron/
├─ main/
│  ├─ index.ts     app lifecycle, the window, and the ipcMain wiring
│  ├─ result.ts    IpcResult — the one shape every handler returns
│  ├─ terminal.ts  the pty registry
│  ├─ workspace.ts directory inspection
│  └─ updater.ts   electron-updater, wrapped in the three calls the UI makes
└─ preload/
   └─ index.ts     contextBridge: `invoke` and `on`, and nothing else
```

`index.ts` holds no logic. Handlers parse arguments, call into a module beside
them, and return its `IpcResult`. That is what keeps the modules testable without
starting Electron.

## The IPC contract

`src/ipc/bindings.ts` is imported by both sides — the renderer and
`electron/main` — so there is one definition of every payload and channel name
and nothing to keep in sync by hand.

`contextIsolation` stays on and the preload surface stays at two functions.
Widening it is how a renderer ends up with `fs`.

## The terminal

`node-pty` owns the pty. It reports the shell exiting through its own `onExit`,
so nothing waits on a read returning EOF — that signal never arrives on Windows,
where the pty's output pipe outlives the child.

On Windows, node-pty ships its own `conpty.dll` and `OpenConsole.exe` and loads
them in preference to the copy inside `kernel32`. The version in Windows 10
deadlocks on teardown and leaves a `conhost.exe` spinning on a full core; that is
why `electron-builder.yml` unpacks `node_modules/node-pty` from the asar, so the
loader can find those files in an installed app.

## CJK input

Chromium delivers composition events correctly, so xterm.js assembles Hangul on
its own and there is no native input path to maintain. This is the reason the app
runs on Electron: under WKWebView the same xterm.js code lost characters, and the
AppKit bridge that worked around it was 350 lines of objc2 with a defect nobody
could close. See the pull request that removed it for the eight attempts.

## Not in this repo, on purpose

- `components/atoms|molecules|organisms` — component size is not the axis that
  matters here; ownership and lifetime are.
- `src/types/`, `src/hooks/` as global buckets — types and hooks live with the
  feature that owns them, so deleting the feature deletes them too.
- Empty scaffolding directories. Create a directory when it has real content.
